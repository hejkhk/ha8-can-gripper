## 0. 一页读懂：项目目标、当前进度、最重要风险

### 0.1 项目究竟要做什么

项目是一套**两指式蜗轮蜗杆夹爪**，使用 **HA8-U35H-M（12V，串口单线半双工）智能舵机**提供动力。当前已经实现一个 Windows/Python/Tkinter 统一上位机：

- 对 HA8 执行通讯检测、角度和状态查询、位置运动、抓取/张开、软件停止等操作。
- 读取夹爪一根手指指尖上的 **IMS003-C10A-1KG** 薄膜力敏电阻（FSR），由电压转换模块转为模拟电压，经 **STM32F103C8T6** ADC 采样和 USB-TTL 上送电脑。
- 进行“**无载归零 → 手动每次闭合 1° → 同步记录压力、舵机电流/角度/时间 → 手动结束并自动分类导出 CSV**”实验。
- 用一次实验中的**压力片理论受力估计**训练一个局部经验模型；在匹配原有实验工况的**闭合运动期间**，尝试不接压力片而仅凭 HA8 电流、角度显示**单指尖局部受力估计**。
- **未来目标**：取消较大的 HA8 官方 USB 转接板，使 STM32 自己完成 HA8 **S 单线半双工**通信和压力 ADC 采样，电脑侧改为单 USB 通信口。**该一体化硬件方案尚未实现/验证**。

### 0.2 现状速览

| 子系统 / 功能 | 交接状态 | 证据与边界 |
|---|---|---|
| HA8 原生串口协议及 Windows 单窗口主程序 | **代码已实现** | `HA8_UpperComputer.py`、`ha8_protocol.py`、`ha8_serial.py`；部分历史通讯实验有记录，不代表每个按钮已完成实机验收 |
| 双 USB COM 自动识别 | **代码 + 模拟测试** | `serial_device_discovery.py`；按 F103 连续有效 P 帧、HA8 只读 Ping 回包区分，双实物环境需复测 |
| F103 ADC 采压并上报 | **代码 + 用户实物观察** | Windows 截图显示 COM4 约 100 帧/秒、按压时 ADC/mV 增大；不构成压力精度验证 |
| 无载零点与换算 | **代码实现** | 无载数据中位数/MAD；`Rf=158kΩ` 为**软件假定值**，未提供万用表核验结果 |
| 每点击一次闭合 1° | **代码 + 自动化测试** | 角度/时效/状态门禁；**不能视为已通过硬件台架运动安全测试** |
| 四类 CSV + `metadata.json` | **代码 + 自动化测试** | 保留 F103 约 100Hz 原始帧、HA8 监控、操作事件与配对结果 |
| 拆除 FSR 后的经验力模型 | **代码 + 离线单测** | 仅特定工况的**闭合运动阶段**，不是完整真实抓力模型；**没有校准精度验收数据** |
| 静止保持力、任意物体抓力及安全力控 | **尚未实现** | 蜗杆可能自锁；电流不等于静态夹持力；不得用作安全防夹或可靠提物判据 |
| STM32 替代官方 HA8 转接板 | **方案设计阶段** | 2026-11-11 新增官方转接板原理图；尚未打样、新固件/新上位机桥接协议均未实现 |

**最重要的五条：**

1. **当前工作链路依旧是两个 USB 串口、一个 GUI**；不要把历史 CAN/CTS100M 桥方案当成现状。
2. **HA8 舵机本体只有 `+ / - / S`**：S 是单线半双工总线，不是独立 TX 和 RX；不能直接把 12V 接 STM32 信号脚。
3. 供应商 FSR **标称最大 1kg**；文档第 2 页虽然含 2kg 曲线参考点，不能据此认定额定量程为 2kg。必须配置机械限位和**独立硬件断电急停**。
4. 现在显示的 `gf/N` 是基于厂家曲线与 **假定 Rf=158kΩ** 的**理论估算**，不是经过标准力计验证的真实抓力。
5. `STOP`/“软件急停”依赖舵机通信和电源，**不是硬件急停**；实验时手、夹持物和传感器均应避开可能发生危险的动作。

```text
                                   │ USB COM A              │ USB COM B
                                   ▼                        ▼
                        官方 HA8 USB/UART 转接板          USB→TTL（3.3V电平）
                                   │                        │
                      3Pin: VIN / IO / GND                USART1 PA9/PA10
```

## 3. HA8 舵机参数、通讯协议与历史关系

### 3.1 厂家资料中的参数

来自用户提供的 `HA8-U35H-M UART 总线舵机技术文档 - 华馨京科技 Wiki(2).pdf` 第 2–3 页（按 12V 型号）：

| 参数 | 参考值 |
|---|---|
| 工作电压 | **9.0–12.6V** |
| 本体接口 | PH2.0 三针，**电源 +、GND -、信号 S** |
| 通讯 | UART / TTL **半双工**，波特率可配；当前使用 **115200 8N1** |
| 默认 ID | 0，允许 0–254；必须以本机读回为准 |
| 内部减速比 | **378:1** |
| 厂家额定输出轴扭矩（12V） | 约 **0.54 N·m** |
| 最大动态参考扭矩（12V） | 约 **1.27 N·m** |
| 静态堵转参考扭矩（12V） | 约 **3.43 N·m**，**不能作为连续保持额定值** |
| 峰值电流 / 空载电流 | 约 3A / 低于 0.2A（参考） |

**厂家扭矩数据已是减速箱输出轴数据**，计算外部蜗轮蜗杆时**不能重复乘 378**。`grip_estimator.py` 的电流→动态参考扭矩数据是对厂商 T-N 图的**粗略人工取点**，不是真实指尖静态力校准。

### 3.2 当前 PC→官方转接板的 HA8 二进制协议

- 请求：`12 4C CMD LEN CONTENT CHECKSUM`
- 回复：`05 1C CMD LEN CONTENT CHECKSUM`
- 校验：前面各字节累加后取低 8 位；串口为连续字节流，需按帧头、LEN、校验和重组，不可假定 `read()` 每次都是一整帧。
- 示例（默认舵机 ID=0）：

```text
Ping 请求：12 4C 01 01 00 60
Ping 回复：05 1C 01 01 00 23
```

主要命令：Ping `0x01`；状态监控 `0x16`；角度查询 `0x0A/0x10`；多圈速度控制 `0x0F`；停止 `0x18`；参数读写 `0x03/0x04`。详见 `ha8_protocol.py`，所有危险写入、设置原点、重置多圈和固件相关功能均须单独验证。

**必须区分**：官方扩展板外侧可以提供 TXD/RXD 两根 UART 线；**舵机本体 S 只有一根收发复用线**，不可在没有方向/开漏控制的情况下把普通 MCU 推挽 TX 与舵机 S 硬连接。

## 4. 官方转接板原理图分析：哪些可以替换，哪些不能随意删

**唯一新上传的该板原理图：**`转接板原理图.pdf`，1 页，图纸日期 2024-12-25，Rev 0.1。以下按**图纸网络名**列出，不代表已经验证每个实体连接器的方向和批次。

### 4.1 关键纠错：CN1 / CN2 脚号

图纸左上角清晰标注：

| CN1 / CN2 脚号 | 对应网络 | 作用 |
|---|---|---|
| **1** | **VIN** | 舵机电源正 |
| **2** | **IO** | 舵机 S 单线通信 |
| **3** | **GND** | 舵机电源负 |

> **严禁直接以旧聊天中的错误脚号接线**：此前曾把 CN1/CN2 写成“1=GND、2=VIN、3=IO”，与本次实际图纸不符。**本表依据原理图修正**。实物仍须结合板载丝印、引脚 1 标志及万用表导通测试确认连接器视角，避免镜像插反。

图纸 J2 另有：`1=VDD`、`2=TXD2`、`3=RXD2`、`4=GND`，这是**转接板侧接口，不是 HA8 舵机 3Pin 引脚**；`VDD` 在图中对应板上逻辑电源，请先实测不要按 12V 推断。

### 4.2 主要器件和功能

| 图纸器件 | 网络/功能（图纸所示） | 一体化设计时的处理 |
|---|---|---|
| **U1 CH340G** | PC USB 与 UART 转换；外接 12MHz 晶振 Y1 | 若 MCU 继续使用外部 USB-TTL，可移除该 USB 转串口功能；若 MCU 以后走 USB CDC，则需另外实现 USB 固件与合规时钟 |
| **U14 SN74LVC1G3157** | 在 `TXD_USB`、`TXD2` 等信号间选择 | 可由统一 MCU 路由替代，但不能直接删除所需的通信调度逻辑 |
| **U2 74HC125PW** | 多路三态缓冲参与 `IO`/TXD/RXD 以及控制使能 | **核心通信接口**：需要由 MCU 半双工 + 开漏/高阻方案或紧凑三态缓冲替代，不能让两端推挽输出争用 |
| **R7 680Ω** | `IO` 线上拉至 `VDD`（逻辑侧） | 必须分析空闲高电平、驱动能力和回包波形；设计上保留可调整上拉位置，值由示波器/电平验证确定 |
| **U3 SGM2203-3.3** | 板上 3.3V 逻辑稳压 | MCU、收发器仍需可靠 3.3V 供电与去耦 |
| **U6 CJ431 / Q2 S8050 / D2 B5819WS** | 与 VIN/USB VBUS/板上 5V 供电关联的电源电路 | 可重设计为受保护的 DC-DC / 电源分配，但**不可简单把舵机 12V 送到 5V/3.3V 逻辑** |
| **D4 SMF15A、EC2、C9 等** | 输入抑制、滤波与储能 | 新板应保留与负载匹配的保护、去耦、接地布局 |

**确认结论**：原板并非“只有 USB 转 TTL”；它还负责电源处理及**S 单线收发的电气接口**。STM32 可以取代其通信决策/USB 适配功能，但**不能把供电、电平保护、上拉和收发争用控制一并省掉**。

## 5. STM32F103 压力采集系统：现有固件及数据协议

### 5.1 现有接线

| F103 / 转换模块 / PC | 连接关系 |
|---|---|
| 转换板 VCC | **5V** 稳压输入（厂家产品参数） |
| 转换板 GND | 与 F103 GND 相连 |
| 转换板 AO | **F103 PA1 = ADC1_IN1**，**先确认不超过 MCU ADC 允许电压** |
| F103 PA9 USART1_TX | USB-TTL RXD |
| F103 PA10 USART1_RX | USB-TTL TXD，必须是兼容 MCU 的 3.3V TTL 电平 |
| F103 GND | USB-TTL GND |
| 转换板 DO | 现有固件未使用，不必连接 |
| F103 PA13/PA14 | SWDIO/SWCLK，留给 ST-LINK 下载调试 |

现有源码/工程在：`extensions/gripper-pressure-f103/`。

### 5.2 已配置的采样参数

- MCU：STM32F103C8T6；CubeMX `.ioc`，HAL 驱动。
- 系统时钟：**HSI 8MHz**，ADC 时钟约 4MHz。
- ADC1 Channel 1 / PA1，12 位，右对齐，软件触发，采样时间 **239.5 cycles**。
- 上电执行 ADC 校准，读数每 **10ms** 一轮（目标约 **100Hz**）。每轮 16 次 ADC 平均，再做 **EMA（alpha=1/4）**；因此输出是滤波后的读数，**不是无延时的原始物理瞬时样本**。
- 使用名义 **VDDA=3300mV**，`mV ≈ round(ADC×3300/4095)`；真实 VDDA 未标定。
- USART1：115200/8N1，主动持续发送文本帧。当前固件**不接收电脑动作命令、不驱动 HA8**。
- 项目源文件有 `.ioc`、`Core/`、Keil `MDK-ARM/`；GitHub **不含完整 STM32CubeF1 HAL/CMSIS Drivers 依赖**。需要在 CubeMX/Keil 环境补齐；重新生成时对比/保留用户采集代码。

### 5.3 串口帧格式及标志

```text
P,seq,mcu_ms,adc,mv,flags\r\n
```

| 字段 | 含义 |
|---|---|
| `P` | F103 压力数据类型 |
| `seq` | 32 位采样序号 |
| `mcu_ms` | F103 开机毫秒计时（不是电脑 UTC） |
| `adc` | 0–4095，滤波后的 ADC 值 |
| `mv` | 按名义 3.3V 换算的毫伏 |
| `flags` | bit0=`1` ADC 读失败；bit1=`2` 接近 ADC 满量程；bit2=`4` 上电校准失败 |

模拟例：`P,42,10025,1744,1405,0`（**仅举例，不是压片已施加 791gf 的证明**）。

固件 ADC 读取失败时可能沿用前次值并设置错误位；不能把异常帧当新鲜受力。上位机对部分高 ADC/异常标志也会抑制力值显示。UART 不是 CRC 完整性协议，上层应进一步校验帧长度、数值、序号和状态。

### 5.4 已观察的实机事实

此前用户 Windows 截图显示压力通道 COM4 已连接、约 100 帧/秒，按压时曲线从空载附近明显上升；截图中某时刻 ADC=1744、输出电压≈1.405V。**仅可证明“AO—ADC—串口—上位机”的响应链路基本有效**，不能推断施加了多少克力，亦不能证明 1–2kg 范围准确。

## 6. 薄膜传感器、厂家压力曲线、158kΩ 算法与零点

### 6.1 传感器规格书是唯一额定量程依据

用户原件：`产品规格书-IMS003-C10A-1KG V1.0.pdf`。第 1 页：量程 **1000g 力**、最小测力约 50g、重复性约 5%、迟滞约 +10%、高负载蠕变明显。第 2 页有**超出标称量程**的 2kg 参考点。

|---:|---:|---:|
| 0 | 无载 >2000（近似无穷大） | 0.0000 |

### 6.2 电压转换模块的理论关系

用户原件：`电压转换模块用户手册8.30+.pdf`。技术参数第 3 页：5V 供电，AO 约 0.1–3.3V，AO-RES 可调 0–300kΩ；第 4 页说明未焊 R2 焊盘断电测阻用于判断反馈电阻，第 5 页给出：

```text
Uo = 0.1 × (1 + Rf/Rx)             （单位：Uo=V；Rf、Rx=kΩ）
G  = 1/Rx ≈ (Uo - Uzero)/(0.1 × Rf)  （单位：G=1/kΩ）
Uo ≈ ADC × 3.3 / 4095
F_gf = 厂家电导—受力表对 G 的分段插值
F_N  ≈ F_gf × 0.00980665
```

- **当前软件把 `Rf=158kΩ` 当作假设固定值**。这是用户为计算指定的暂定参数，**没有万用表实测确认记录**。调节 AO-RES 后必须更新并重新验算。
- `Uzero` 取实际无载时 ADC 中位数对应的电压。仅能校正**偏置**，不能校正反馈电阻、传感器个体差、接触位置和迟滞。
- 供应商手册明确表示该压力片不适合作精密测力计；软件的 gf/N 应始终标注“**理论估计、未经标准力验证**”。

**理论电压（仅计算展示，VDDA=3.3V、Rf=158kΩ）**：

| 受力 | Rx | 理论 AO |
|---:|---:|---:|
| 50gf | 160kΩ | 约 0.199V |
| 100gf | 90kΩ | 约 0.276V |
| 200gf | 49kΩ | 约 0.422V |
| 500gf | 18kΩ | 约 0.978V |
| 1000gf | 9.8kΩ | 约 1.712V |
| 2000gf（超标称） | 5kΩ | 约 **3.260V**，距离标称 AO 满幅仅约 40mV，容易饱和 |

### 6.3 必须执行的无载零点

1. 将 FSR 安装于实际指尖位置，夹爪**完全松开，接触面确实无载**，不允许在保持夹紧的状态下清零。
2. 接 F103 和官方 HA8 设备，等待压力帧稳定约 1 秒。
3. 在统一 GUI 的“**压力验证 / 曲线**”点击 **“① 无载归零（采最近1秒）”**。
4. `pressure_validation.py` 使用最近数据**中位数 + MAD 稳定性检查**，记录 `zero_adc`、噪声；必须有足量有效帧才允许开始实验。
5. “② 开始标定采集”前会复核近期帧、通讯和读数是否回到零点附近；采集中**禁止重新归零**。断开/重连压力串口后必须重校零。
6. 归零只能作用于本次有传感器的实验；成功保存的**离线经验模型**使用时不要求仍连着 F103，但精度和适用工况仍受限。

**注意**：软件只能检查读数稳定、接近先前零点，不能物理证明“传感器真的完全无载”；操作人员必须自己确认。

## 7. 统一 Windows GUI 的使用与实际标定操作

### 7.1 连接两个 COM

- HA8：电脑 USB → **官方转接板** → 舵机，默认 115200/8N1；上位机通过**只读 Ping**识别其回包。
- F103：电脑 USB-TTL → F103 USART1，默认 115200/8N1；F103 持续上报 `P,...` 文本数据。
- 根 GUI 有 **“自动识别并连接两设备”**：先被动监听 F103 的两个有效连续压力帧，再对安静端口发送指定 ID 的 HA8 Ping；如果识别重复、端口占用或不能确定，不会乱选，支持手工连接。
- 首次运动前进入“**夹爪控制**”，开启 HA8 监控，验证舵机 ID、当前角度、电流及机械闭合方向。**角度减小=闭合**是当前软件约定，必须先和实物核对。
- GUI 右上角“显示高级调试”包含风险较高的底层操作；交接初期不要修改固件/原点/多圈参数。

### 7.2 一次实验的标准流程（V3.7）

1. **上电前机械检查**：确认安全区域无人、固定工装、指尖压头对准压力片、不剪切滑动、物理限位及独立硬件断电急停已就绪；12V 电源和 F103 电源均正确。
2. **连接与清零**：两路 COM 连接成功，FSR 完全无载稳定 1 秒，按“① 无载归零”；实时观察 ADC、mV 和估算 gf/N。
3. **设置边界**：在“夹爪控制”输入并实机验证最小抓取角度 / 最大张开角度，低速、低功率；不允许只凭猜测设大行程。
4. **开始实验**：回到“压力验证 / 曲线”，点击“② 开始标定采集（先归零）”，勾选“已确认独立硬件急停、闭合方向、机械限位和安全距离”。
5. **人工逐度动作**：每点击一次“**闭合 1°（单次）**”，软件尝试发送“当前实际 HA8 反馈角度 − 1°”的目标指令；必须等待**连续有效到位反馈**，下一度才可继续。压力、角度、电流等一直记录。**不会自动循环压到 2kg**。
6. **停止与留样**：操作者可随时点击“**完成记录并自动导出**”。如果目标尚未到位，软件将尝试发送 STOP/HOLD，**仍需人工确认实际停止**。异常、超时、电流或压力失效时不继续操作。
7. **分析与建模**：查看四类 CSV 和 `metadata.json`；需要试用离线模型时，在 GUI 点击“**从本次数据生成并保存模型**”。这一步是另一个动作，**完成 CSV 导出并不自动等于模型已生成**。

**当前软件的保守步进限制（用于实验，不是可靠力保护）**：速度会被限制到不高于约 `5°/s`，运动功率不高于约 `1500mW`；超过已设置的机械角度下限拒绝继续；软件见到理论估算受力接近 **900gf**、帧异常、压力数据超时、未到位、舵机状态异常时拒绝进一步步进/尝试 STOP。**压力片的物理精度未经验证，900gf 不是可以代替硬件限力的安全阈值**。

### 7.3 软件关闭或断连

- 正在采集时关闭 GUI / 断开 HA8 / F103：程序尝试终止记录并自动导出。若磁盘写入失败，可能留下未完整写出的文件，操作员必须核实目录内的数据数量。
- 一旦 F103 断连，下一次标定必须重新采无载零点；上一次生成并保存的离线模型文件不会因此自动失效或重新训练，但应记录其使用工况。
- 对任意真正危险动作，必须使用物理电源急停、机械限位和人工监护；软件停止不是安全认证装置。

## 9. “标定一次以后不用压力片”：当前模型的真实含义

**源码**：`grip_force_calibration.py`，数据来源 `pressure_validation.py::CurveRecorder`。

1. 使用采集到的 `(current_A, angle_deg, phase, theoretical_gf)` 作为样本，要求当前是**同一舵机正在闭合**，状态正常，FSR 理论受力在 **50–1000gf** 内，HA8 与压力样本时间差不超过约 **180ms**。
2. `ForceMap.train()` 至少要求 **18 个有效点**，电流跨度至少 **0.04A**、角度跨度至少 **0.5°**、理论受力跨度至少 **80gf**；否则拒绝生成。
3. 模型**不是带物理意义的电流–扭矩模型**，当前是在二维 `(电流,角度)` 上找最接近的 **7 个样本**进行局部加权平均，离群/出界时返回“无法估计”。
4. 保存位置：`calibration/grip_force_model.json`，这是**单台设备、单个夹具与单次工况的本地数据**，不应当成官方通用参数上传仓库；加载模型时会校验格式/来源及“未经独立验证”标记。
5. 之后可拆除 FSR/F103，但只允许在**原测试覆盖的电流/角度范围、闭合运动阶段**给单指尖参考 gf；**静止保持、自锁、张开、异常或未知物体工况不估算**，更不能用于力控/自动停止。
6. 若要显示夹口距离 `mm`，必须补充两组**实物测量的**“舵机角度—两指开口距离”锚点；当前仅在两点区间内做线性插值，不是完整机构模型。

### 9.1 为什么还不能将其称为“精确抓力标定”

- FSR 是压阻元件：受力区域、压头、安装预紧、迟滞、蠕变、材质变化都会影响读数。
- 即使 `Rf=158kΩ` 精确，也只是获得厂家**平均电阻—力参考曲线**，不等于对**这一片**传感器完成绝对力校准。
- 一个 FSR 只位于**一个指尖的某一接触位置**。它测量的是局部法向力，不等于两指接触力简单相加，也不等于可防滑承载的物体质量。
- **蜗轮蜗杆可能自锁**，停止后大部分夹紧力可能由机构摩擦/结构弹性维持，电流大幅下降；静止电流无法唯一推断保持力。
- 不同物体硬度、尺寸、夹口位置、运动/停止历史可能对应不同的“电流、角度→力”关系。离线算法的良好训练拟合不能代替留出轮次的实测检验。

**研究建议**：先保留 FSR 完成至少一组独立验证，分别记录“闭合→到位保持→卸载→重复加载”；分析模型残差、迟滞、静态力保持和跨物体差异，再决定是否可长期拆除。需要安全限力时应保留可信实时力反馈或增加独立扭矩/应变测量。

## 10. 外部蜗轮蜗杆、运动学与拟议 URDF 工作

用户已确认：外部蜗轮**模数 1、20 齿**；蜗杆**模数 1**；FSR 一片安装在一根指尖；HA8 内部减速箱 378:1。

```text

输出轮力矩近似：   T_wheel ≈ T_HA8_output × i_w × η_w
```

### 11.2 电气方案必须验证

- STM32F103 的 USART 支持单线 Half-Duplex 模式，可先试 **USART2 TX=PA2**，使用**开漏/可切换高阻**的电气驱动方式、合适的 3.3V 上拉和共地；回包时严格让出总线，避免舵机与 MCU 推挽输出冲突。
- **不推荐首版把 PA2 直接裸连舵机 S 就视为成功**。更稳妥的打样方式是保留类似原 `74HC125` 的受控三态缓冲、限流、ESD 及测试点，通过逻辑分析仪/示波器先确认空闲、低高电平、方向切换、响应时序以及舵机上电/断电状态。
- 原板图纸 `R7=680Ω` 上拉至 VDD；新板上拉电阻与拓扑是否可沿用，需结合电平上升时间和总线拉低电流**实测**决定。切勿凭一个推荐值替代验证。
- F103 3.3V 稳压必须可靠；若移除 CH340 做 F103 原生 USB CDC，需要设计 USB D+/D−、ESD、晶振/PLL 时钟、USB CDC 固件和端点协议，**并非只换一根 USB 线**。
- 确认正确供电/公共地/隔离与急停方案。应保留舵机电源过流/欠压和 F103 模拟采样的滤波、退耦、模拟地布局，不直接照搬官方板上 5V 电路而忽略发热与负载。

### 11.3 固件与 PC 侧需要新开发的项目

- 新固件应包含 F103 单线 HA8 协议发送/回包解析、收发方向/超时/故障状态机、ADC 采样、双任务优先级或非阻塞调度、连接断线策略。
- 一条 USB 串口同时承载 HA8 命令回包和压力样本时，**必须设计区分通道的上位机↔STM32 帧格式**（例如类型、长度、序号、校验及可用的透明传输/回应机制）；当前 HA8 二进制帧与 F103 ASCII `P,...` 不能不加复用约定就随意混发。
- 现有上位机目前假定“两套独立 COM”。单 USB 桥接完成后，必须升级 `ha8_serial.py`/`pressure_validation.py`/`serial_device_discovery.py` 或抽象为新的单口复用驱动，并保留当前双 COM 可回退方案。
- 在**示波器确认之前**只能发送 Ping/只读监控，不得直接进行自动夹取；随后再验收 1° 低速空载位移、故障与急停行为。

### 11.4 建议分阶段验收（先单向只读，后动作）

| 阶段 | 验收内容 | 通过标准 |
|---|---|---|
| H0 | 绘制并核对官方板 CN/IO/VIN/GND、逻辑电平、HA8 电源 | 图片/表格/万用表证据、无短路或 12V 入 GPIO |
| H1 | STM32 经原板 TTL 侧查询 HA8 | Ping、角度、电流数据与原 GUI 一致；不发送动作 |
| H2 | STM32 通过自建 S 单线接口查询 HA8 | 帧校验正确、半双工无冲突、长时间读回稳定 |
| H3 | 上位机只用一个 COM 控制与读取压力 | 压力帧与 HA8 回包可区分；序号、CRC/校验、丢帧与断线恢复可测 |
| H4 | 低速、限角、低功率空载 1° 动作 | 正确方向/到位，STOP、超时、断线能被验证 |
| H5 | 在工装上跑安全范围内标定 | 4 类数据与原双 COM 结果可对照，无明显通讯争用 |

**这五阶段均为下一版本工作清单。现在不能把它们写成已通过。**

### 12.2 历史问题与当前处理

| 问题 | 当前说明 |
|---|---|
| Keil `Error: Flash Download failed - Cortex-M3` | 历史曾遇到；检查 ST-LINK 连接、SWD 频率、供电/BOOT0、Flash 算法；不是 HA8 或压力软件逻辑错误的直接证据 |

| 曾出现两个独立上位机 | 当前已统一为仓库根 `HA8_UpperComputer.py`；旧压力 GUI 已从当前代码树删除，保留 Git 历史 |
| 标定过程中零点改变 | 现有代码锁定零点，断线重连需重新采；有旧数据时清零会提示 |
| 以前只能留下配对后的数据 | V3.7 已新增 F103 全部串口帧、HA8 监控、步进事件和配对数据分别导出 |
| 历史说明出现 CAN/CTS100M 或旧 `protocol.py` 路径 | 是旧文档和旧通信架构；**以最新根 README、本交接和当下代码为准** |
| 高载压片输出“2kg” | 厂家参考曲线有该点，但 **1kg 仍是标称工作量程**；不得当认证测力范围或安全阈值 |
| 静止夹持时电流下降 | 可能与蜗轮蜗杆自锁有关；当前模型静止时明确拒绝预测，不是软件 bug 能靠线性拟合消除 |

### 12.3 工程残余风险

- 当前没有实测的指尖法向力误差表，也没有一份能证明**去掉 FSR 后泛化抓力精度**的独立测试报告。
- 单指尖局部受力不能直接推断双指总夹紧力、防滑能力或可搬质量。
- `doc/HA8_official_reference.md` 历史版本有“当前使用 USB-CAN→CTS100M”的旧段落，和当前主 README 冲突，必须按**实际代码与新交接**判定；其他 V3.1/V3.2 历史文档也可能有过期引脚和使用说明。
- 目前 GUI 每点击 1° 的实验电机动作通过 HA8 串口发出；尽管有检查和软件限幅，**设备仍可能因执行延迟、反馈错误、换向、机构碰撞而出现危险**。硬件急停、可视区域和操作员监护必不可少。
- 现有源码和 CI 未验证“STM32 直连 HA8 S”的新电路，也未包含新半双工 USART 固件。**不要直接刷现有 F103 压力固件就期待它控制舵机**。

## 13. 给下一位开发者的建议工作顺序（先复现，后改动）

### 第一天：只读熟悉

1. 克隆仓库，记录 `git rev-parse HEAD`，先阅读根 `README.md`、`doc/MANUAL_STEP_CSV_CALIBRATION_2026-10-30.md` 和本文。
2. 阅读 `ha8_protocol.py`、`ha8_serial.py`、`pressure_protocol.py`、`pressure_validation.py`，了解**两种互不兼容的串口帧**。
3. 运行两组 Python 单测和语法检查；安装和启动 GUI，检查无硬件状态下不会自动动作。
4. 核对实物部件、接线、供电、急停，尤其注意**CN1/CN2 1=VIN、2=IO、3=GND**，并核对真实连接器方向。

### 第二天：恢复现有双 COM 正常工作

1. **单独**连接官方 HA8 转接板，先 Ping/只读监控；记录真实 ID/电压/电流/角度，禁止盲目大行程。
2. **单独**连接 F103 压力模块，验证 115200 ASCII P 帧、空载 ADC/按压方向、在采样范围内无持续异常标志。
3. 两个设备都稳定后打开统一 GUI；小行程确认闭合方向、限位与低功率动作。
4. 用**安全、无载**的压力片采一次零点并记录参数；不要在受压时清零。
5. 分段逐度闭合一次，手动结束、确认自动生成五个文件；画出原始时间曲线核对无数据混乱和无错误单位。

### 第三天及以后：研究实测、再评估单板重构

1. 补齐 URDF/STEP、蜗杆头数、机械尺寸、指尖法向力方向、已知法向载荷基准；不要凭猜测填写几何参数。
2. 做安全范围内的多轮**加载—保持—卸载**实验，保留一部分数据不参与训练，先测模型泛化误差。
3. 如果实验证实依靠电流和角度无法推断静态保持力，明确限制用途或**保留实时力传感器**，不要将算法包装成可靠测力仪。
4. 若进行 STM32 单线半双工替代设计，按 **H0→H5** 的顺序做可回退验证；软件/硬件改动先开分支和 PR，通过 CI 后再合并。

## 16. 最终交接结论（不可删改的边界）

**到 2026-11-11，本项目已具备一套“HA8 官方串口控制 + F103 压力采集 + 统一 Windows 实验上位机 + 逐度记录和分类 CSV + 实验性离线力映射”的代码体系。** 压力片—电脑的 ADC 变化链路有用户实物观察，主仓库相关软件有 CI 自动化测试。

**它现在还不是**已知精度的夹爪抓力测量仪、可以离线准确测量任何物体静态夹持力的系统，更不是力控安全闭环。**“取消官方转接板，仅用一片 STM32 单线半双工接 HA8 + ADC 读取 FSR”是明确的下一阶段硬件研发任务，尚未实现。**

接手人的第一优先级是**确认真实硬件及通信、完成安全范围内的可复现标定并取得完整 CSV**；在核对机械 URDF/STEP、蜗杆头数和实际压力误差之前，不应承诺抓力精度，更不应将理论 gf 作为自动继续夹紧的唯一依据。
