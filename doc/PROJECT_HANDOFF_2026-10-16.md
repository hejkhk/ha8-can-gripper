## 一、交接摘要（接手者先读）

本项目要制作一个用于六轴机械臂的**两指式蜗轮蜗杆夹爪**，由华馨京/Fashion Star **HA8-U35H-M** 串口总线舵机驱动。机械侧希望完成张开、闭合、夹物，后续希望从电流和角度识别是否接触/疑似抓住物体。早期目标曾讨论夹取约 **3 kg**，但该目标**没有通过力、摩擦、滑移、结构强度和实际负载测试验证**。

**现在采用的唯一推荐调试链路：**

```text
Windows 电脑（Python/Tkinter）
       │ USB，枚举为 COMx
       ▼
HA8 官方 USB 串口驱动/扩展转接板
       │ 由转接板实现 HA8 所需单线半双工通信
       ▼
HA8-U35H-M → 蜗杆 → 蜗轮/夹爪机构 → 两指末端
       ▲
       └── 适配舵机额定电压的独立电源（项目原方案为 24V→12V DC-DC）
```

**现阶段不要误用旧链路：**“USB-CAN → CTS100M → HA8”及“STM32F103C8T6 → CAN → CTS100M → HA8”是历史调试方案，相关代码/资料仅用于参考；V3.2 主程序不调用这些设备。

**当前已有：**

1. V3.2 测试上位机与原生 USB 串口收发模块。
2. 单圈/多圈运动、角度/状态读取、ID 扫描、参数读写、标定、同步/异步、原始帧调试界面。
3. 实验性电流→**动态输出轴参考扭矩**估算及“疑似接触/疑似夹持稳定”状态机。
4. **自动抓取测试**页面：抓取、张开、软件急停/解锁、当前电流/角度、最小抓取角度和最大张开角度等。
5. 协议、状态机与界面部分离线测试，GitHub Actions 语法及单元测试工作流配置。

**尚未完成：**实体夹爪全流程验收、输出扭矩/末端夹持力标定、物体防滑确认、失联时确保安全停止、可靠的自动抓稳判断、与机械臂的动作安全联锁。**不能将“疑似夹持稳定”作为自动抬升 3 kg 物体的许可。**

## 二、硬件组成与接线

| 组件 | 用途 | 现有认识/约束 |
|---|---|---|
| HA8-U35H-M（12 V 版） | 夹爪致动器 | 原生 UART 总线舵机，默认设备 ID 为 0；舵机本体为 GND/VDD/SIGNAL 单线半双工接口 |
| 官方舵机转接/扩展板 | USB 串口及半双工转换 | 上位机应直接选其 Windows COM 口；不要把舵机 SIGNAL 当成普通双线 TX/RX |
| 24 V→12 V 降压模块（原定方案） | 为舵机提供合适电压 | 实测前应核查所购具体舵机铭牌、转接板供电说明、降压电源电流能力与极性 |
| 蜗杆、蜗轮、两指夹爪 | 扭矩传递与夹紧 | 传动比、效率、摩擦、自锁、夹爪力臂随开口变化；目前无完整实测标定 |
| Windows 电脑 | 运行 Python 上位机 | 用户此前在 `gemini_yolo` Conda 环境、Windows PowerShell 下运行 |

连接注意：

- 若直接使用官方带 USB 的转接板，按官方转接板的具体接线及供电定义连接，不再加 CTS100M/CAN 模块。
- 若改用独立 USB-TTL：通常 USB-TTL TX→扩展板 RX、RX←扩展板 TX、GND↔GND；**仅在扩展板明确提供双线 UART 引脚时适用**。TTL 不可直连 RS-232 ±12 V 信号。
- 舵机的 S 单线不是独立的 TX 和 RX；扩展板承担半双工方向转换。
- 调试台应具备可独立切断舵机电源的**实体急停/断电措施**。软件停止按钮不能替代它。
- **当前未得到经过测量的机械闭合终点、张开终点、有效夹持区间、实际闭合方向**。设置前不能使用自动抓取功能。

### 历史 CAN 方案（非当前实施链路）

## 五、HA8 原生串口通讯协议（接手开发必须理解）

### 5.1 报文与校验

**PC→舵机请求：**

```text
12 4C | CMD(1) | LEN(1) | CONTENT(LEN) | CHECKSUM(1)
```

**舵机→PC 应答：**

```text
05 1C | CMD(1) | LEN(1) | CONTENT(LEN) | CHECKSUM(1)
```

`CHECKSUM = sum(之前所有字节) & 0xFF`。`LEN` 是 CONTENT 的字节长度，不包含帧头、CMD、LEN、CHECKSUM。字节序为小端（具体字段以 `ha8_protocol.py` 为准）。串口是一条**无包边界的字节流**，接收回调分块与 HA8 帧边界不对应；`ResponseStreamParser` 按帧头、长度与校验恢复完整回复。新版 USB 直连发送**整条 HA8 帧**，不按 8 字节拆 CAN 帧。

**Ping（ID=0）**：

```text
TX: 12 4C 01 01 00 60
RX: 05 1C 01 01 00 23
```

**单圈角度查询（ID=0）**：

```text
TX: 12 4C 0A 01 00 69
RX 示例: 05 1C 0A 03 00 FD FF 2A  → -0.3°
```

**多圈角度读取（ID=0）**：`12 4C 10 01 00 6F`。读取角度解码到 `angle_deg`（单位 °）。

### 5.2 主要指令对照

| CMD | 作用 | 程序入口 |
|---|---|---|
| `0x01` | Ping | 通讯检测 |
| `0x02` | 恢复用户数据 | 参数读写；高风险 |
| `0x03` / `0x04` | 读/写参数表 | 参数读写 |
| `0x08` / `0x0B` / `0x0C` | 单圈运动：简易/指定时间/指定速度 | 位置控制 |
| `0x0D` / `0x0E` / `0x0F` | 多圈运动：简易/指定时间/指定速度 | 位置控制、自动抓取 |
| `0x09` | 阻尼控制 | 停止/标定 |
| `0x0A` / `0x10` | 单圈/多圈角度读取 | 位置控制 |
| `0x11` / `0x17` | 重置多圈 / 设置原点 | 停止/标定；高风险 |
| `0x12` / `0x13` | 异步开始/执行或取消 | 同步/异步；需核对固件 |
| `0x16` | 状态监控 | 数据监控、夹持检测、自动抓取 |
| `0x18` | 停止命令（释放/保持/阻尼） | 停止/标定、自动抓取的软件停止 |
| `0x19` | 同步指令 | 同步/异步；需核对固件 |

`STOP_RELEASE=0x10`、`STOP_HOLD=0x11`、`STOP_DAMPING=0x12` 为 `CMD 0x18` 的 **method 字段**，不要与指令 CMD 混淆。软件急停当前调用 `HA8Protocol.stop(..., STOP_HOLD, power)`。

### 5.3 监控回复结构

`CMD 0x16` 的请求为 `HA8Protocol.monitor(servo_id)`。目前解码器按结构 `<BHHHHBih` 解码：

| 字段 | 类型 | 单位/用途 |
|---|---|---|
| `id` | uint8 | 设备 ID |
| `voltage` | uint16 | mV |
| `current` | uint16 | mA；界面除以 1000 显示 A |
| `power` | uint16 | mW |
| `temperature_adc` | uint16 | 温度 ADC（由工程算法转换成近似 °C） |
| `status` | uint8 | 故障/运行状态位 |
| `angle` | int32 | 0.1°，显示时除以 10 |
| `turn` | int16 | 圈数 |

状态字：bit0 执行中；bit1 指令错误；bit2 堵转；bit3 过压；bit4 欠压；bit5 电流错误；bit6 功率错误；bit7 温度错误。当前自动抓取主要检查 `status & 0xFC`（bit2～bit7）；**bit1 指令错误尚未包含在这一判断中，是后续需要评审的风险**。

发送命令≠已经执行；收到监控回包≠急停动作已被硬件确认。后续应增加停止后的位姿/速度确认、协议超时与重试策略，并结合硬件断电急停。

## 六、软件架构与数据流

```text
HA8_UpperComputer.py（Tk 主线程）
  ├─ ha8_protocol.py  [纯协议封装 / 回包解码]
  ├─ ha8_serial.py    [pyserial / 后台读取线程]
  ├─ GripPanel        [手动夹持诊断页]
  │    └─ grip_estimator.GripDetector  [纯算法]
  └─ AutoGripPanel    [自动抓取台架测试页]
       └─ grip_estimator.GripDetector  [新会话，复用部分阈值]

串口输入：ha8_serial 后台读线程
    → UI 队列 → _pump_ui_queue
    → ResponseStreamParser.feed
    → decode_response
    → HA8_UpperComputer._apply_response
    → 数据监控显示 / CSV / GripPanel.on_monitor / AutoGripPanel.on_monitor

发送：GUI 事件 → HA8Protocol.move / stop / monitor / ...
    → HA8_UpperComputer.send_ha8
    → HA8SerialTransport.send_ha8 → pyserial 写完整 UART 帧
```

- `HA8Protocol` 不依赖 GUI 和串口，便于单元测试。
- `HA8SerialTransport` 有后台读线程和写入锁，按完整帧校验并输出；它不是硬实时通信模块。
- GUI 使用 Tkinter 主线程更新控件，使用 `after()` 做周期任务。
- `GripPanel` 与 `AutoGripPanel` 是**不同的检测会话**：手动诊断和自动抓取虽复用 `GripDetector`，但本身各自维护状态；不能将一个页面的“夹稳”直接理解成另一页面已停止或抓取成功。
- 自动抓取目前直接复用主窗口的 `send_ha8` 和监控，**没有独立的运动命令仲裁器**。接手者应处理多个页面同时发运动/停止/监控命令时的竞争与紧急停止优先级。

## 八、电流—动态扭矩估算与夹持判定

### 8.1 电流并不直接等于夹持力

厂家 12 V 舵机 T-N 特性图提供扭矩、电流、转速与效率关系，但当前用于上位机的数字点是**根据图片近似读取的参考点，不是厂家给出的逐点标定表**：

| 回报电流（A） | 参考输出轴动态扭矩（N·m） |
|---:|---:|
| 0.30 | 0.30 |
| 0.40 | 0.50 |
| 0.50 | 0.75 |
| 0.60 | 1.00 |
| 0.70 | 1.20 |

在相邻两点之间使用线性插值。**以下情况返回“不适用”：**电流不在 0.30–0.70 A 范围内，或检测到的角速度不足约 2 °/s（静止/保持）。`current_ma` 是否与原厂绘图时的电流测量定义相同尚未确认。

- 这一列最多表示**舵机输出轴在动态运动时的扭矩参考**；不是蜗杆后扭矩，更不是末端夹紧力、摩擦裕度或允许提升质量。
- 蜗杆自锁、空载摩擦、夹爪力臂几何、传动效率、保持电流降低都能导致“电流 ↔ 夹持力”关系失效。
- 官方参数中额定扭矩约 0.54 N·m、最大动态扭矩约 1.27 N·m、静态堵转扭矩约 3.43 N·m属于**不同工况**，禁止按“3.43 N·m÷3 A”简单建立统一换算比例。

### 8.2 当前默认夹持检测阈值

| 参数 | 默认值 | 解释 |
|---|---:|---|
| 空载电流基线 | 0.20 A | **示例值**，应实测当前工况空载电流 |
| 接触增量 | 0.18 A | 滤波电流需达到基线+增量（示例为 0.38 A） |
| 候选最低电流 | 0.55 A | 候选夹持条件之一，**不是确认抓稳阈值** |
| 异常电流上限 | 1.50 A | 单次原始电流越线优先锁存异常；不是硬件保护 |
| 低速条件 | ≤2 °/s | 配合电流判断疑似接触 |
| 接触确认 | 约 0.20 s | 低速与高于基线电流持续 |
| 夹持稳定确认 | 约 0.50 s | 达候选电流且低速持续 |
| 最小有效闭合行程 | 2° | 当前代码默认 |
| 反馈超时 | 1.50 s | 手动诊断状态机超时锁存 |
| 夹持角度上下限 | 默认为空 | 不填写时**不输出“夹持稳定候选”** |
| 滤波窗口 | 最近 5 个样本取中位数 | 降低毛刺影响，但无法测滑移 |

手动检测流程：先点击“开始一次夹持检测”使 `GripDetector.arm()`，在确定闭合方向与夹持角度区间后，通过位置页发闭合指令；算法观察电流、角速度、行程、持续时间和 `status` 保护位：

```text
未开始 → 闭合观察中 → 疑似接触 → 疑似夹持稳定（未校验）
                                 ↘ 条件丢失可回退
任意阶段遇堵转/保护位、超限电流 → 异常（需要重新开始）
反馈间隔超过阈值 → 超时（需要重新开始）
```

`GripState.CANDIDATE` **不代表夹紧力充足、不代表物体未打滑、不代表安全抓取完成**。无实际测力/防滑试验，无法声明抓 3 kg 可行。

### 8.3 **V3.2 自动抓取的停止时机，与“稳定候选”不同**

`auto_grip_panel.py` 实际使用下面的逻辑：

1. 确认 COM 已连接、自动监控已开启、当前反馈新鲜、舵机无 `status & 0xFC` 保护位、没有软件急停锁存；验证用户填写的角度范围与方向。
2. “抓取”：向**最小角度**发送多圈速度模式位置运动 `0x0F`；为本次闭合创建一个独立 `GripDetector`，其电流阈值来自“夹持检测”页当前**已应用**的设置，并强制闭合方向为 `-1`。
3. 监控反馈出现 `GripState.CONTACT` **或** `GripState.CANDIDATE` 时便调用 `_send_hold()` 发送 `CMD 0x18 / STOP_HOLD 0x11`；**并不会必须等到 0.55 A、0.5 s 的稳定候选才停止**。在默认基线下，电流约 0.38 A、速度下降并经过接触确认即可触发停止（还需满足行程及采样条件）。
4. 即使未遇接触，也会在反馈角度进入 `最小角度+0.8°` 附近尝试停止；这表示达到**行程下限**，**不表示抓到了物体**。
5. “张开”：向**最大角度**发送同样的多圈速度模式运动，监控到 `最大角度-0.8°` 附近发送保持停止。
6. 监控发现堵转/保护位、反馈超时 `0.65 s` 或任务时长超过 `20 s` 时，会**尝试**下发保持停止并锁存软件急停。
7. “一键急停（软件）”按钮下发保持停止并禁止新动作，必须在确认机构安全后人工解锁。**此过程没有硬件断电，也没有停机成功的闭环确认**。

**重大工程差异：**现有自动抓取实现的实际目标是“**遇到疑似接触就停止闭合**”，不是“保证达到所需夹持力后闭合结束”。因此它**可能在接触初期停止得太早、夹力不够**。此外，停止后电流可能下降，不能用最后一帧电流证明夹紧力。接手者必须用实验区分“检测到接触”“达到目标夹持力”“真实抓稳并可搬运”，避免错误地将三个状态合并。

## 九、安全机制：现状与待改善问题

### 已写入程序（但尚需实机确认）

- 角度上下限默认空，未设置禁止自动抓取/张开；要求 `抓取最小角度 < 张开最大角度` 且名义行程至少 3°。
- 自动抓取仅支持“闭合角度减小，张开角度增大”；起步时检查当前角度在允许范围附近。
- 起步必须有最近 `0.65 s` 内的监控反馈，运行中定期检查超时。
- 若出现 `status` 位 2～7 报警、过流/检测异常或任务超时，尝试发送保持停止。
- 停止指令只在一个终止条件首次触发时发送，避免重复下发；日志保留停止原因。
- 软件急停锁存，需人工确认解除。

### **P0 风险（上线、接机械臂或夹重物前必须处理）**

1. **软件急停不具备安全等级。** USB 断线、舵机失电、电脑卡死、串口忙、固件拒绝指令时，`_send_hold` 可能发不出去；发送成功也不代表动作停止。需要**独立硬件急停及实际停机反馈**，并验证失联时的物理安全状态。
2. **可能误判夹紧：**当前自动抓取在 `CONTACT` 即停止，甚至没有达到稳定候选阈值；无末端测力、缺乏夹持力模型及滑移试验。不可用于自动抬升/搬运人体附近负载。
3. **机械限位未标定**：最小/最大角度按用户手输，软件边界未结合制动距离、夹爪惯量、物体压缩和真实硬限位；接近角度发送停止可能来不及。
4. **命令仲裁缺失**：主位置页与自动抓取测试页可能竞争发指令；监控询问也共享同一个 UART 通道。需要独立动作所有权/优先级、紧急停止优先队列、串口故障恢复与停止状态确认。
5. **异常位检查不全**：`status & 0xFC` 未包含 `bit1`（指令错误）；应明确评估是否拒绝运动并警示。
6. **参数不绑定真实夹爪**：运动速度/功率上限是通用界面值，未经机械传动与负载验证。限制默认值不能视为物理安全裕度。
7. **停止目标 ID**：自动控制停止时使用主窗口当前选中的设备 ID，而不完全使用启动时锁定的 ID；如果运行途中改变舵机 ID，有误停其他设备的风险。应以动作会话快照 ID 为准，运行中锁住切换。
8. **自动夹持监控与手动诊断耦合**：自动页读取 `GripPanel` 已应用设置；操作者可能以为修改输入框立即改变了自动抓取阈值，实际上需先点击“应用参数”。应统一配置来源、显式显示生效配置和会话快照。
9. **停止与报警只是软件反应**：无独立电流采集核对、通信 CRC 之外的物理反馈验证；状态可能丢失、动作不可确认，须增加位置稳定/速度估算和最大扭矩/最大电流硬件保护测试。

## 十、完整实机验收顺序（建议由接手者执行）

**不得跳过前置步骤直接测试夹重物或一键自动抓取。** 先将夹爪固定于台架，清除夹持区域的手指、线缆和障碍，配备独立可断电急停，电源限流、低速低功率、空载测试。

| 顺序 | 内容 | 通过标准/需记录的数据 |
|---|---|---|
| 0 | 检查固件版本、供电、板卡接线、紧急断电 | 串口设备、供电电压、舵机 ID、固件型号明确 |
| 1 | COM 连接、Ping | 收到预期 ID 的合法 HA8 回包，不出现串口占用或校验错误 |
| 2 | 单圈/多圈角度读取 | 手动微动机构时角度变化、方向与实际一致，无突变/圈数错误 |
| 3 | 空载小角度运动 | 低速小行程可控，明确“角度减小=闭合”是否真实成立 |
| 4 | 手动 STOP_RELEASE / STOP_HOLD / STOP_DAMPING | 每条指令响应、机械是否实际停止、是否继续承载/可能松爪均记录 |
| 5 | 监控采集 | 电流 mA、功率 mW、角度、状态字与真实工况一致；记录 CSV、接收频率 |
| 6 | 机械角度标定 | 测出无损坏条件下的张开/闭合硬限位，另设软件安全限位和提前停止裕度 |
| 7 | 电流基线 | 空载闭合全行程电流随角度/速度变化曲线，而不只取空闲单值 |
| 8 | 软接触物体 | 采集不同材质/厚度物体接触前后电流峰值、角度速度、保护位变化 |
| 9 | 夹持检测算法 | 对照接触真值，检查误报、漏报、硬限位误判、振动/回弹后误报 |
| 10 | 自动抓取空载台架 | 确认极限角度、停止延迟、故障锁存、再次动作须人工解除 |
| 11 | 异常注入 | 模拟串口中断/拔线、反馈停止、错误状态、在途 ID 切换、错误角度参数 |
| 12 | 抓取负载分级测试 | 在屏障与保护措施下逐级测夹力/滑移/掉落；做不了就不声称负载能力 |

建议每一轮至少保存：**操作时间、设备 ID、固件、波特率、12V 实测电压、抓取/张开角度上下限、速度/功率设置、原始监控 CSV、失败照片/视频、是否触发保护、实际停止情况**。

监控 CSV 当前除时间/ID/电压/电流/功率/温度/状态/角度/圈数外，还会记录：`dynamic_torque_ref_Nm`、`angle_speed_dps`、`grip_state`、`grip_note`。当前 CSV 格式由 `HA8_UpperComputer.export_monitor_csv` 维护；如未来新增自动抓取任务级状态，建议额外加入动作编号、目标角度、发出 Stop 时间与确认 Stop 时间。

## 十二、历史事故与排错经验

- **仓库误删事故：**V3.0 迁移官方 USB 串口时曾误删 `ha8_protocol.py`、`requirements.txt`、旧协议文档和测试文件，造成 `ModuleNotFoundError`。后续已恢复。任何代码迁移都应先对比文件增删列表，**不要只看功能差异**。
- **缩进事故：**`ha8_protocol.py` 曾把 `elif CMD_MONITOR` 与 `struct.unpack` 错误合并到同一行，出现 `IndentationError: unexpected indent`。已修复；在每次提交中保留语法测试。
- **通讯混用事故：**USB-CAN 厂商 CDC 的 20 字节封包、F103 透明 UART 流、HA8 原生 UART 帧是**三套不同的主机通讯方式**。V3.2 应只发送原生 HA8 帧，不要混入 CAN ID、20 字节封包或把完整 HA8 命令拆成 8 字节。
- **结果语义混淆：**“电流到 0.55 A”≠“夹持成功”；“动态参考扭矩”≠“静态夹持力”；“发送保持停止”≠“舵机已经停止”；“软件急停”≠“硬件急停”。
